# MiNVR 飞牛 fnOS 真机安装验证清单

> 适用版本：minvr_0.2.1.fpk（镜像随包离线安装方案）
> 用途：在真实 fnOS 设备上确认 FPK 安装后 MiNVR 可正常运行。

## 前置条件
- fnOS 已安装，App Center 可用（或已通过 Moo 源 / 手动上传 FPK 安装）。
- 设备已通过 SSH 开启终端访问（用于跑验证脚本）。

## 一、安装方式（任选其一）
1. **Moo 源**：App Center → 设置 → 第三方源 → 添加本仓库地址 → 搜索 MiNVR 安装。
2. **手动上传**：App Center → 本地安装 → 选择 `minvr_0.2.1.fpk`。
3. 安装完成后**不要**依赖外网拉镜像——离线镜像已随包打入（amd64 / arm64）。

## 二、自动验证（推荐）
SSH 登录 fnOS，执行：

```bash
# 下载脚本到设备后运行（默认路径 /var/apps/minvr/target）
bash verify-install.sh

# 若 APPDEST 非默认，可指定：
APPDEST=/var/apps/minvr/target bash verify-install.sh
```

脚本会逐项检查并输出 `[PASS]/[FAIL]/[WARN]`：
- 基础环境（docker / compose）
- FPK 解包内容（镜像 tar、compose）
- 本地镜像 `minvr:0.2.1` 是否已导入
- 容器 `minvr` 是否运行
- WebUI `/` 与 `/api/health`（含 `mediaReady`）
- 容器内 go2rtc / ffmpeg 二进制
- 数据目录
- （可选）米家登录：设 `MIHOME_USER` / `MIHOME_PASS` 后脚本会测登录接口

## 三、手动验证（脚本不可用时的兜底）
```bash
# 1) 镜像是否导入
docker images | grep minvr

# 2) 容器是否运行
docker ps | grep minvr

# 3) WebUI
curl -s http://localhost:8080/api/health

# 4) 查看日志（起不来时）
docker logs --tail 50 minvr
```

浏览器访问 `http://<NAS_IP>:8080` 应能打开配置页。

## 四、常见失败与处理
| 现象 | 原因 | 处理 |
|---|---|---|
| `[FAIL] 缺少当前架构镜像包` | FPK 不完整 | 重新下载并校验 sha256（应为 `c55d8517...da51`，365095568 字节） |
| `[FAIL] 镜像 minvr:0.2.1 不存在` | install_callback 的 `docker load` 未执行 | 手动 `docker load -i $APPDEST/docker/minvr_<arch>.tar` |
| `[FAIL] 容器未运行` | compose up 失败 | `docker logs --tail 50 minvr` 看报错；常见为端口 8080 冲突 |
| `[WARN] mediaReady 非 true` | go2rtc 未就绪 | 等数秒重试；仍不行看容器日志 |
| WebUI 打不开但 health 200 | 前端资源问题 | 看后端日志，确认 `public/` 已进镜像 |

## 五、米家接入说明
- 登录走社区标准 `account.xiaomi.com` 三步 + `api.io.mi.com` 签名枚举，未用真实账号验证过。
- 若自动登录失败：在 WebUI 走「手动添加摄像头 → 米家直连」，填入设备 IP / DID 即可。

## 六、回滚 / 卸载
- App Center 直接卸载 MiNVR 即可；本地镜像 `minvr:0.2.1` 会残留，可 `docker rmi minvr:0.2.1` 清理。
